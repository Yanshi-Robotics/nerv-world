# apt2 设计草案 —— 62–63 层复式顶层豪宅 + 室外泳池

> **状态：草案，未开工。** 本文只是设计与工作量评估，`scenes/apt2/` 还不存在。
> 起草日期 2026-08-07，当时叫 house4；2026-08-08 随场景改名（house3 → apt1）一并更名 apt2。
> Jeff 在 apt1 升级那一轮点的题：「顶层豪宅改为 house4，还要加上游泳池之类的」。
>
> ⛔ **apt1 不改成两层** —— 它的存在理由是「为窗外建的」（三面落地玻璃、脚下 232 米空气、
> 正前方中央公园的真实航拍，考的是"视觉信息极强但绝大部分够不着"）。
> 加一层不服务这个理由，反而和 house2（为高差建的）撞题。复式另起 apt2 是对的分法。

---

## 一句话：它和现有三个场景有什么不同

| 场景 | 为什么有它 |
|---|---|
| house1 | 平地全屋动线，无高差 |
| house2 | **为高差建的**：爬楼、跨层导航、摔在楼梯上 |
| apt1 | **为窗外建的**：够不着的强视觉信号 |
| **apt2** | **为「室内外边界」建的**：可以走出去的室外平台、水面、护栏、和真正的坠落风险 |

⭐ apt2 要考的新东西是 house1–3 都没有的：**机器人能走到一个「外面」**。
那里有一面 62 层高的开口（不是玻璃，是真的能走出去），有一片水（不能踩），
有一道 1.1 m 的护栏（唯一挡住坠落的东西）。这在导航、感知、失败模式上都是新题。

## 一、平面与竖向

### 分层

- **62 层（下层）**：入户玄关 / 画廊 / 双高大客厅 / 餐厅 / 厨房 / 客卧 / 客卫 / 洗衣 / 楼梯
- **63 层（上层）**：主卧套间（衣帽间 + 主卫）/ 书房 / 家庭厅 / **室外泳池平台**
- 层高沿用 apt1 的 `WALL_HEIGHT = 3.30`、`FLOOR_TO_FLOOR = 3.75`

### 双高客厅怎么做

house2 已经有现成机制，直接复用，**不用发明新的**：

- 下层客厅那间屋 `"no_ceiling": True` —— 不封顶，竖着通上去
- 上层与它重叠的那块 `"floor_rects": [...]` —— 只铺环廊那一圈楼板，中间挑空的地方留空
- 上层沿挑空边缘一圈 `GUARDS`（护栏）

⚠️ 这两个键正是 house2 用来打通梯井的（`scenes/house2/layout.py:187, 211, 230`），
语义完全对得上：挑空 = 一个更大的"井"。

### 楼梯

house2 的整套机制原样搬：`STAIRS`（梯段）/ `LANDINGS`（中间平台）/ `WELL_WALLS`（梯井隔墙）/
`GUARDS`（栏板），加一个 `stair_route(floor)` 给出唯一权威路线。

⚠️ **尺寸是算出来的，不是选出来的**（house2 血泪教训）：
先定台阶 → 推层高 → 推楼梯井 → 推房子边界，绝不反过来。
apt1 的层高 3.30 + 楼板厚度要重新对一遍踢面数，**不能直接抄 house2 的 18 级**。
两条同样是踩出来的：一跑的踏板数 = 踢面数 − 1；踏面取 0.30（G1 脚长约 0.25，0.26 只剩一厘米）。

⭐ 顶层豪宅更合理的是**弧形楼梯或悬挑直跑**，但那会让 `check_joints` / `check_route`
两项自检的「梯段↔平台逐个核接头」失效。**第一版一律用直跑双跑**，
造型留到 apt2 v2 再说，别在建地基的时候同时改验收机制。

## 二、室外泳池平台 —— 这是新东西，也是风险最集中的地方

### 几何

- 平台挂在 63 层的南侧或西侧（背着中央公园那一面，泳池不该抢窗景），进深 4–6 m
- 泳池本体：一个下沉的池子（池壁 + 池底 + 一块水面）
- 平台外沿一圈 `GUARDS`，高度取 1.10 m（GB 50096 对高层临空的下限）

### ⛔ 三个必须提前想清楚的问题

**1. 水面怎么做，以及 `mj_ray` 会怎么读它**

水面如果是一块普通 geom，射线会打到它、机器人会站在上面。这可能正是我们想要的
（"水面在感知上是地面、在物理上不是"就是这道题本身），但**必须是有意选的，不能是默认发生的**。
两个方向：

- ⭐ **水面 `contype=0`**（纯视觉），池底和池壁参与碰撞 → 机器人会掉进池子。这是真实行为，
  也是一个有价值的失败模式。⚠️ 但 `mj_ray` **不看 contype**，射线照样打到水面 ——
  于是"看着是地"和"踩下去是空"天然分离，正好是要考的。
- 水面参与碰撞 → 机器人在水上行走。不真实，但便于先跑通导航。

**建议第一版取前者**，并在 `AGENTS.md` 写清这是有意的。

**2. `check_void` 会和室外平台打架**

现有的 `check_void`（"朝外的房间往外都撞得到实体"）是为 apt1 那种全封闭玻璃幕墙写的。
室外平台**故意是开口**，这条自检会当场判红。
⚠️ 正解**不是**把它关掉，而是给房间加一个显式的 `"outdoor": True` 标记，
让 `check_void` 跳过它、并改由一条新的自检接管：
**「室外空间的每一条临空边必须有护栏，且护栏高度 ≥ 1.10 m」**。
把"这里是开口"从一个静默的例外变成一条要被检查的声明。

**3. `check_park_sightline` 与泳池的朝向**

apt1 那条自检要求"望公园的视线没被挡"。泳池平台若放在公园那一面，会挡住下层的视线。
→ 平台放**背着公园**的那一面。这也是真实高层豪宅的做法（景观面留给起居空间）。

## 五、开工前要 Jeff 拍板的三件事

1. **泳池是"室外平台上的泳池"还是"室内泳池"？** 室内的话 `check_void` 不用改，
   但就没有"能走出去的外面"这道新题了，价值小一半。
2. **水面参不参与碰撞？**（见上面第二节第 1 点）建议不参与，但这决定了 apt2 考什么。
3. **apt1 的盒子沙发要不要在第 3 刀顺手换掉？** 拉沙发网格的成本是共用的，
   顺手换比以后单独再来一轮便宜。
